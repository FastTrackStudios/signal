# Block ports: a block's named outputs, routed by port (signal#28)

A block can have several outputs: a multi-mic sampler's `in`, `oh` and
`room`, a piano's close and tree, a guitar rig's DI and amp. Each is
routable to another lane like any other audio. Nothing here is
drum-specific.

## What is in (slice 1)

- **The block contract** (`plugin_processors::BlockProcessor`):
  `output_count()`, `output_name(i)`, and `output(i) -> (&[f32], &[f32])`
  hold that output's audio over the last piece the block processed, at
  the block's own level. Effects have none. A block that has outputs still
  processes its first in place, so a chain doesn't change because of them.
  The outputs are filled during `process` from preallocated buffers, with
  no allocation. A family block forwards them to its engine.
- **The graph** (`signal_core::graph`): a **send by port**,
  `SendSpec { to, gain_db, port: Some(BlockPort { block, port }) }`
  (built with `SendSpec::to(lane, db).port(block, port)`), takes that
  block's named output instead of the lane's audio.
  - It's taken where the block puts it out, before the lane's fader, and
    `pre` doesn't apply.
  - Delay compensation counts the chain *up to and including that block*.
    A port is therefore sample-aligned with the block's other outputs and
    with everything else reaching the destination.
  - When the piece passed the block by (bypassed, or its phase off), the
    send is silent and its delay line still runs.
  - A port the block doesn't have is a build warning.
- **The chain read**: each block lists its `outputs` (names) in
  `signal.chain/1`, and the build report carries them
  (`BlockReport::outputs`).
- **The `drum` block**: when its `.signalengine` has more than one port,
  each engine port is one of its named outputs. The first port is what it
  plays in place (as before), and all of them play at the block's `level`.
  This uses `SamplerBank::port_names` and `render_with_ports`. A one-port
  engine (every MM2 piece today: `mic "default"`) has no named outputs and
  costs nothing extra.

Tests: `features/core/tests/block_ports.rs`. A non-drum "piano" with
`close` and `room` behind a 64-frame lookahead sends `room` to a bus,
which nulls against half the close mic on the same frame (< 1e-7). The
send is silent when the block is bypassed, and an unknown port is a
warning. The drum block's port wiring is only compile-checked: there is
no multi-port engine fixture yet (slice 4).

## What is next

2. **Across instances** (Studio's per-track mode). Each kit track runs its
   own Signal instance, and `Cymbals/OHs` isn't in the piece's instance, so
   a send by port to it can't land inside one graph. There are two ways,
   both on this contract:
   - **(a) the host's routing (preferred):** the CLAP declares an extra
     stereo audio output port per block port (`clap_plugin_audio_ports`,
     named `<block>/<port>`), filled from `output(i)`. The host routes a
     plugin output pin to the track that should carry it. This works on
     any DAW that routes plugin outputs (REAPER does). Studio's engine
     needs plugin output pins routed to tracks (the daw repo), plus
     `signal.chain/1` saying which pin is which port.
   - **(b) the Signal session's own bus:** a port published to the session
     (like the hits on `HitBus`) as a lock-free ring per port, which a lane
     of another instance takes as an input (`LaneSpec` `from: {lane, block,
     port}`) a block late. That is the remote keys' lookahead, already
     paid by keyed ports. It is quicker to land, but Signal-only, and the
     host's delay compensation can't see it.
3. **Studio's kit**: a piece's `Sample` lane sends `oh` to `Cymbals/OHs`
   and `room` to `Rooms` (through 2a's pins or 2b's bus). Its close ports
   stay on the piece.
4. **Library side**: per-piece engines with the packs' mic layers as ports
   (MM2: kick In/Out/Sub, snare Top/Bottom, toms, OH, Room), generated by
   the pack tooling. This is also the fixture slice 1's drum test needs.
   The other sampler-family block (`sampler`, `.signalpreset` graphs)
   exposes its ports the same way once its engines have them.
